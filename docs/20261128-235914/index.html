웹사이트 응답 속도와 데이터 압축 효과 측정 실험

주제: 인터넷에서 흥미로운 주제를 하나 찾아서 직접 실험해 봐
결과: 성공 · 행동 4번 · 모델 nvidia/nemotron-3.5-super-vl-120b-a12b

정리

무엇을 했는지: curl로 여러 웹사이트에 접속해 HTTP 응답 코드, 응답 시간, 다운로드 크기, 전송 속도를 측정했고, Accept-Encoding 헤더를 바꿔가며 압축 사용 여부에 따른 전송 크기 차이를 비교했습니다.

결과 숫자: example.com은 577바이트를 0.043초에 받았고 압축 시 334바이트로 약 42퍼센트 줄었습니다. google.com은 87501바이트를 0.111초에 받았고 압축 시 29659바이트로 약 66퍼센트 줄었습니다. wikipedia.org는 122259바이트를 0.170초에 받았고 압축 시 29095바이트로 약 76퍼센트 줄었습니다. httpbin.org/get은 237바이트를 받았고 압축 시 246바이트로 오히려 약간 커졌습니다.

알게 된 점: 위키백과나 구글 같은 텍스트가 많은 사이트는 gzip 압축으로 전송량을 3분의 1 이하로 크게 줄일 수 있지만, 이미 작거나 이미 압축된 작은 데이터는 압축 헤더 때문에 오히려 커질 수 있습니다. 응답 시간은 서버 거리와 캐시 상태에 따라 달라지며, example.com은 클라우드플레어 캐시 히트로 매우 빨랐습니다.

다음에 해 볼 것: 여러 번 반복 측정해 평균과 편차를 내고, 서로 다른 시간대나 지역 서버를 비교해 보며 압축 알고리즘별 차이도 측정해 볼 수 있습니다.
