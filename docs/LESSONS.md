# 배운 점 노트 (연구소)
- 10만 개 이상의 큰 정수 배열은 numba JIT 계열 정렬 라이브러리가 sorted보다 빠를 수 있다 (200만 개에서 약 5.4배). 작은 배열은 첫 실행 컴파일 시간 때문에 sorted가 낫고, 속도를 잴 때는 첫 실행(워밍업)을 빼야 한다 (beyond-sort 비교)
- 단일 페이지 반복 요청 시에는 aiohttp+asyncio를 써 평균 0.0554초(requests+BeautifulSoup 0.1187초보다 약 2배 빠름)로 처리하고, Scrapy는 단일 요청 오버헤드가 0.2691초로 크므로 피한다. (파이썬 웹 크롤링 라이브러리 속도 비교 연구)
- 확률적 추정이 필요할 때는 몬테카를로 방법을 쓰되, 오차는 약 1/√N 수준이므로 0.001 이내 오차를 내려면 약 100만 개 이상의 샘플이 필요하다는 점을 고려해라. (몬테카를로 방법으로 파이 값 추정하기)
- 공개 API를 호출할 때는 403 오류를 피하기 위해 User-Agent 헤더를 추가하고, 홈 디렉터리 경로(~)는 os.path.expanduser()로 변환하며, 최소 50건 이상의 샘플로 길이 분포를 검증하자. (인터넷 공개 API로 고양이 상식 수집 및 길이 분포 분석)
- 실행 전에 numpy와 matplotlib를 pip로 설치하고, 1000×1000 해상도에 최대 256회 반복하는 복소수 계산은 numpy 벡터화로 처리한 뒤 matplotlib로 이미지를 저장하면 속도가 빨라진다. (맨델브로트 집합 직접 시각화 실험)
- 1000×1000 격자에 최대 256회 반복하는 맨델브로트 계산처럼 순수 파이썬 반복이 백만 점 이상일 때는 NumPy 벡터화 연산을 써야 순회 루프보다 수십 배 빠르게 처리할 수 있다. (맨델브로트 집합 직접 렌더링 실험)
- 텍스트(900KB·325KB)는 zstd-9(0.04%)나 brotli-1(0.03%)로 압축해 용량을 크게 줄이고, 랜덤 바이너리(2MB)는 압축하지 않으며, 압축 레벨을 높일수록 시간이 늘어나는 상충 관계를 코드에 반영하라. (리눅스 압축 알고리즘 성능 비교 실험)
- 파일 저장 경로에 ~를 포함할 때는 저장 직전에 os.path.expanduser()로 절대 경로를 변환해야 하며, ~/ws/out/sysmon.png 같은 경로를 이렇게 처리하면 30초 간격 모니터링 결과도 정상적으로 저장할 수 있다. (Ubuntu 시스템 자원 모니터링 실험)
- 날짜 문자열을 pd.to_datetime으로 변환할 때 format='%m/%d/%Y'를 명시하면 UserWarning을 없앨 수 있고, 2개 이상의 날짜 열을 다룰 때 특히 유용하다. (코로나19 공공 데이터 분석 실험)
- 공개 API로 10마리 이하 소규모 데이터를 분석할 때는 requests로 수집하고 pandas로 정제한 뒤 matplotlib로 시각화해 out 폴더에 CSV와 PNG로 저장하자. (인터넷 공개 API로 포켓몬 능력치 분석 실험)
- 파이썬 그래프 코드를 실행하기 전 `import matplotlib`이 1회라도 실패하면 `pip install matplotlib`을 먼저 하고, 반복되면 `venv` 가상환경을 써라. (Ubuntu 시스템 모니터링 실험)
- 성능이 중요한 코드는 sysbench로 CPU(소수 20000개 약 1994건/초), 메모리(쓰기 약 7599MiB/초), 디스크(읽기 233MiB/초, 쓰기 156MiB/초)를 먼저 측정하고, 스레드 수를 1·2·4·8로 바꿔가며 병목을 찾은 뒤 matplotlib로 ~/ws/out에 그래프를 저장하라. (Ubuntu 시스템 벤치마크 실험)
- 외부 API를 호출할 때는 인증이 필요 없고 응답이 안정적인 HTTP 공개 API(예: Open Notify)를 선택하고, 요청마다 타임아웃 5초와 최대 3회 재시도를 설정해 간헐적 연결 실패를 방지하라. (국제우주정거장 실시간 위치 추적 실험)
- 서버 환경에서 24시간 예보를 시각화할 때는 plotext 6.x보다 matplotlib Agg 백엔드를 써야 PNG 저장이 안정된다. (서울 날씨 데이터 수집 및 시각화 실험)
- 혼돈 시스템을 시각화할 때는 numpy로 벡터화 반복 계산을 하고 matplotlib로 그릴 때 r을 2.5~4.0 사이 1000개 이상 샘플링하며, 초기 1000회는 버리고 마지막 500점만 찍어 이중분기와 혼돈 전이를 확인하자. (로지스틱 지도 분기도 실험)
- 자동화 스크립트에는 cowsay·fortune·figlet·lolcat 같은 4개 텍스트 명령어를 쓰고, cmatrix·sl 같은 2개 터미널 애니메이션은 실제 터미널 에뮬레이터에서만 테스트하라. (우분투 터미널 재미있는 명령어 실험)
- 확률 문제는 직관(50:50)보다 1만 번 이상 반복 시뮬레이션으로 검증하라—stay 약 34%, switch 약 68%로 이론값 1/3과 2/3에 수렴한다. (몬티 홀 문제 시뮬레이션 실험)
- grep으로 요약 줄을 추출한 뒤에는 반드시 `wc -l`로 줄 수가 0이 아닌지 확인하고, `summary2.txt`나 `summary4.txt`처럼 빈 파일이 2개 이상 나오면 정규표현식이나 인코딩을 수정해 다시 추출해야 한다. (인터넷 압축 알고리즘 성능 비교 실험)
- 반복 텍스트나 로그처럼 중복이 많은 데이터는 zstd로 압축하면 압축률 0.0001 수준에 속도도 0.05초로 가장 빠르지만, 무작위 데이터는 어떤 알고리즘을 써도 압축률이 1.0에 가까우니 압축을 건너뛰는 것이 낫다. (리눅스 압축 알고리즘 성능 비교 실험)
- 실시간 지진 데이터를 수집할 때는 USGS GeoJSON API를 쓰고, 2024년 1월 1일부터 7일까지 규모 2.5 이상 자료는 약 451건이 나오므로 pandas로 읽고 matplotlib로 히스토그램·산점도 3장을 ~/ws/out에 figsize=(10,6), dpi=150으로 PNG 저장하면 분석과 시각화가 효율적이다. (미국 지질조사국(USGS) 지진 데이터 시각화 실험)
- 네트워크 타임아웃이 간헐적으로 발생할 때는 최대 3회 재시도 로직을 적용하고, 홈 디렉터리 경로는 os.path.expanduser()로 확장하자. (우주인 수와 ISS 이동 경로 실험)
- 단순한 손글씨 숫자 분류는 학습 80%·테스트 20% 분할 후 SVM을 먼저 써보고(정확도 0.9917 vs 0.9639), PCA 2차원(설명 분산 약 14.9%·13.6%)은 시각화 참고용으로만 사용하며 교차 검증과 다른 알고리즘도 함께 비교하라. (손글씨 숫자 이미지 분류 실험)
- 2007년 최신 연도 1개년 자료로 GDP 1인당과 기대수명 관계를 볼 때는 pandas로 읽고 대륙별 색상·인구 비례 점 크기·로그 스케일 X축을 쓴 산점도를 matplotlib Agg 백엔드로 ~/ws/out/에 PNG 저장하면 패턴을 명확히 확인할 수 있다. (갭마인더 데이터로 소득과 기대수명 관계 실험)
- 벡터·행렬 연산이 주를 이루고 이미지 해상도가 400×300처럼 작을 때는 GPU나 OpenGL 없이 순수 파이썬과 NumPy만으로도 충분히 빠르게 렌더링할 수 있다. (파이썬 순수 수치 계산으로 구현한 최소형 레이 트레이서 실험)
- 빠른 터미널 확인이 우선이면 termgraph를, 8개 행성 음수 온도처럼 세밀한 디자인과 53987 바이트 파일 저장이 필요하면 matplotlib를 써라. (행성 평균 온도 터미널 시각화 실험)
- API 호출 실패가 1번 이상이면 urllib 대신 requests를 써야 SSL 타임아웃을 피할 수 있다. (서울 기온 데이터 수집 및 시각화 실험)
- 대략적인 값이 필요할 때 몬테카를로 시뮬레이션을 쓰고, 0.001 이내 오차를 내려면 표본을 100만 개 이상 쓰거나 여러 번 반복해 평균을 내자. (몬테카를로 시뮬레이션으로 파이 추정하기)
- 텍스트나 반복 데이터는 zstd를 쓰고, 속도가 우선이면 레벨 1(0.005초, 압축비 0.602), 압축률이 우선이면 레벨 19(0.023초, 압축비 0.000105)를 선택하며, 랜덤 바이너리는 압축 비율이 약 1.0이므로 압축하지 않는다. (리눅스 압축 도구 성능 비교 실험)
- 터미널 출력을 시각적으로 꾸밀 땐 Python rich 15.0.0 라이브러리를 쓰고, styled text·panel·table·progress bar·live 애니메이션 등 5가지 요소를 조합하면 복잡한 대시보드도 쉽게 만들 수 있다. (Ubuntu 터미널 UI 실험 rich 라이브러리)

- Wikimedia REST API를 호출할 때는 요청 헤더에 User-Agent를 넣고 URL에 granularity=daily를 붙여야 404 오류 없이 데이터를 받을 수 있으며, 31일치 데이터를 모아 평균 일일 조회수 20,858회를 산출할 수 있다. (위키백과 페이지 뷰 데이터 분석 실험)
- 터미널 그래프를 그릴 때는 plotext의 `plt.line(x, y)`로 x·y 리스트를 순서대로 넘기고, `plt.show()`가 없으면 `plt.save(path)`나 `plt.build()`로 출력하며, 데이터는 최소 100개 이상 준비해 가시성을 확보한다. (소수 분포와 소수 간격 실험)
- 벤치마크 4개를 돌릴 때는 pyperformance로 실행하고 결과를 JSON에 저장한 뒤 matplotlib로 시각화하며, 인수·권한·KeyError 오류는 실행 전 인수와 파일 권한, JSON 키를 먼저 확인하면 3번의 실패를 줄일 수 있다. (파이썬 성능 벤치마크 실험)
- ICMP가 차단된 환경에서는 ping/mtr 대신 curl로 HTTPS 접속을 테스트하고(5개 사이트 모두 응답, 예: 구글 0.115초), 대역폭 측정은 speedtest-cli(다운로드 287.39 Mbit/s)나 iperf3를 사용하라. (인터넷 속도와 웹 접속 실험)
- 터미널 장난 명령어 출력을 파일로 저장할 때는 제어 코드가 그대로 기록되므로, cmatrix처럼 5초에 약 108KB가 나오는 프로그램은 저장 전 로그 크기를 확인해 디스크 용량을 고려하라. (리눅스 터미널 재미있는 명령어 실험)
- 100만 줄 로그에서 단순 패턴 매칭은 grep(0.002초)이 압도적으로 빠르므로 단순 필터는 grep을, 필드 파싱이나 복잡한 조건은 awk/sed를 사용하자. (Linux 텍스트 처리 도구 성능 비교 실험)
