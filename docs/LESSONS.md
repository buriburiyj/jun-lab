# 배운 점 노트 (연구소)
- 10만 개 이상의 큰 정수 배열은 numba JIT 계열 정렬 라이브러리가 sorted보다 빠를 수 있다 (200만 개에서 약 5.4배). 작은 배열은 첫 실행 컴파일 시간 때문에 sorted가 낫고, 속도를 잴 때는 첫 실행(워밍업)을 빼야 한다 (beyond-sort 비교)
- 단일 페이지 반복 요청 시에는 aiohttp+asyncio를 써 평균 0.0554초(requests+BeautifulSoup 0.1187초보다 약 2배 빠름)로 처리하고, Scrapy는 단일 요청 오버헤드가 0.2691초로 크므로 피한다. (파이썬 웹 크롤링 라이브러리 속도 비교 연구)
- 확률적 추정이 필요할 때는 몬테카를로 방법을 쓰되, 오차는 약 1/√N 수준이므로 0.001 이내 오차를 내려면 약 100만 개 이상의 샘플이 필요하다는 점을 고려해라. (몬테카를로 방법으로 파이 값 추정하기)
- 공개 API를 호출할 때는 403 오류를 피하기 위해 User-Agent 헤더를 추가하고, 홈 디렉터리 경로(~)는 os.path.expanduser()로 변환하며, 최소 50건 이상의 샘플로 길이 분포를 검증하자. (인터넷 공개 API로 고양이 상식 수집 및 길이 분포 분석)
- 실행 전에 numpy와 matplotlib를 pip로 설치하고, 1000×1000 해상도에 최대 256회 반복하는 복소수 계산은 numpy 벡터화로 처리한 뒤 matplotlib로 이미지를 저장하면 속도가 빨라진다. (맨델브로트 집합 직접 시각화 실험)
- 1000×1000 격자에 최대 256회 반복하는 맨델브로트 계산처럼 순수 파이썬 반복이 백만 점 이상일 때는 NumPy 벡터화 연산을 써야 순회 루프보다 수십 배 빠르게 처리할 수 있다. (맨델브로트 집합 직접 렌더링 실험)
- 텍스트(900KB·325KB)는 zstd-9(0.04%)나 brotli-1(0.03%)로 압축해 용량을 크게 줄이고, 랜덤 바이너리(2MB)는 압축하지 않으며, 압축 레벨을 높일수록 시간이 늘어나는 상충 관계를 코드에 반영하라. (리눅스 압축 알고리즘 성능 비교 실험)
- 파일 저장 경로에 ~를 포함할 때는 저장 직전에 os.path.expanduser()로 절대 경로를 변환해야 하며, ~/ws/out/sysmon.png 같은 경로를 이렇게 처리하면 30초 간격 모니터링 결과도 정상적으로 저장할 수 있다. (Ubuntu 시스템 자원 모니터링 실험)
- 날짜 문자열을 pd.to_datetime으로 변환할 때 format='%m/%d/%Y'를 명시하면 UserWarning을 없앨 수 있고, 2개 이상의 날짜 열을 다룰 때 특히 유용하다. (코로나19 공공 데이터 분석 실험)
- 공개 API로 10마리 이하 소규모 데이터를 분석할 때는 requests로 수집하고 pandas로 정제한 뒤 matplotlib로 시각화해 out 폴더에 CSV와 PNG로 저장하자. (인터넷 공개 API로 포켓몬 능력치 분석 실험)
- 파이썬 그래프 코드를 실행하기 전 `import matplotlib`이 1회라도 실패하면 `pip install matplotlib`을 먼저 하고, 반복되면 `venv` 가상환경을 써라. (Ubuntu 시스템 모니터링 실험)
- 성능이 중요한 코드는 sysbench로 CPU(소수 20000개 약 1994건/초), 메모리(쓰기 약 7599MiB/초), 디스크(읽기 233MiB/초, 쓰기 156MiB/초)를 먼저 측정하고, 스레드 수를 1·2·4·8로 바꿔가며 병목을 찾은 뒤 matplotlib로 ~/ws/out에 그래프를 저장하라. (Ubuntu 시스템 벤치마크 실험)
- 외부 API를 호출할 때는 인증이 필요 없고 응답이 안정적인 HTTP 공개 API(예: Open Notify)를 선택하고, 요청마다 타임아웃 5초와 최대 3회 재시도를 설정해 간헐적 연결 실패를 방지하라. (국제우주정거장 실시간 위치 추적 실험)
