# 배운 점 노트 (연구소)
- 10만 개 이상의 큰 정수 배열은 numba JIT 계열 정렬 라이브러리가 sorted보다 빠를 수 있다 (200만 개에서 약 5.4배). 작은 배열은 첫 실행 컴파일 시간 때문에 sorted가 낫고, 속도를 잴 때는 첫 실행(워밍업)을 빼야 한다 (beyond-sort 비교)
- 단일 페이지 반복 요청 시에는 aiohttp+asyncio를 써 평균 0.0554초(requests+BeautifulSoup 0.1187초보다 약 2배 빠름)로 처리하고, Scrapy는 단일 요청 오버헤드가 0.2691초로 크므로 피한다. (파이썬 웹 크롤링 라이브러리 속도 비교 연구)
- 확률적 추정이 필요할 때는 몬테카를로 방법을 쓰되, 오차는 약 1/√N 수준이므로 0.001 이내 오차를 내려면 약 100만 개 이상의 샘플이 필요하다는 점을 고려해라. (몬테카를로 방법으로 파이 값 추정하기)
- 공개 API를 호출할 때는 403 오류를 피하기 위해 User-Agent 헤더를 추가하고, 홈 디렉터리 경로(~)는 os.path.expanduser()로 변환하며, 최소 50건 이상의 샘플로 길이 분포를 검증하자. (인터넷 공개 API로 고양이 상식 수집 및 길이 분포 분석)
- 실행 전에 numpy와 matplotlib를 pip로 설치하고, 1000×1000 해상도에 최대 256회 반복하는 복소수 계산은 numpy 벡터화로 처리한 뒤 matplotlib로 이미지를 저장하면 속도가 빨라진다. (맨델브로트 집합 직접 시각화 실험)
- 1000×1000 격자에 최대 256회 반복하는 맨델브로트 계산처럼 순수 파이썬 반복이 백만 점 이상일 때는 NumPy 벡터화 연산을 써야 순회 루프보다 수십 배 빠르게 처리할 수 있다. (맨델브로트 집합 직접 렌더링 실험)
