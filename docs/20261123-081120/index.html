리눅스 압축 알고리즘 성능 비교 실험

주제: 인터넷에서 흥미로운 주제를 하나 찾아서 직접 실험해 봐
결과: 성공 · 행동 13번 · 모델 nvidia/nemotron-3.5-super-vl-120b-a12b

정리

위키피디아에서 데이터 압축 원리를 확인한 후, Ubuntu에서 gzip, bzip2, xz, zstd, pigz 다섯 가지 압축 도구를 직접 실험했습니다. 테스트 파일은 반복 텍스트, 랜덤 텍스트, 랜덤 이진, 영(0) 이진 각 약 1MB씩 생성했고, 압축 비율과 압축 시간을 3회 측정해 평균을 내었습니다.

결과: 반복 텍스트는 zstd가 0.000 비율로 가장 작게 압축했고, bzip2와 xz도 0.000으로 우수했습니다. 랜덤 텍스트는 모든 알고리즘이 0.724~0.732로 비슷했으며, zstd가 0.0179초로 가장 빨랐습니다. 랜덤 이진은 압축이 불가능해 1.000에 가까웠고, zstd와 pigz가 가장 빨랐습니다. 영 이진은 bzip2와 zstd가 0.000으로 극도로 압축했습니다.

알게 된 점: 데이터 특성에 따라 최적 압축 알고리즘이 다릅니다. zstd는 압축률과 속도의 균형이 가장 좋았고, 랜덤 데이터는 어떤 알고리즘으로도 압축할 수 없었습니다. 그래프는 ~/ws/out/compression_benchmark.png에 저장했습니다.

다음에 해 볼 것: 압축 해제 속도 측정, 더 큰 파일로 실험, 실시간 스트림 압축 테스트.

For most LZ methods, this table is generated dynamically from earlier data in the input. The table itself is often Huffman encoded . import subprocess, os, time, statistics

files = ["text_repeat.txt", "text_random.txt", "bin_random.bin", "bin_zero.bin"]
compressors = ["gzip", "bzip2", "xz", "zstd", "pigz"]

results = []

for f in files:
    orig = os.path.getsize(f)
    for c in compressors:
        times = []
        comp_size = None
        for run in range(3):
            t0 = time.time()
            with open(f, "rb") as fin, open("/tmp/out", "wb") as fout:
                p = subprocess.run([c, "-c", "-9"], stdin=fin, stdout=fout)
            t1 = time.time()
            if p.returncode != 0:
                break
            comp_size = os.path.getsize("/tmp/out")
            times.append(t1 - t0)
        if comp_size is None:
            continue
        ratio = comp_size / orig
        avg_t = statistics.mean(times)
        results.append((f, c, orig, comp_size, ratio, avg_t))
        print(f"{f:20s} {c:6s} orig={orig:8d} comp={comp_size:8d} ratio={ratio:.3f} time={avg_t:.4f}s")

print("\nDone.")
